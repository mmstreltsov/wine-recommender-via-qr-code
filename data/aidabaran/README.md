## Фото: CDN + локальный fallback

- Основной источник — CDN Тильды ресторана: открытый CORS, hotlink без ограничений,
  ресайз на лету подстановкой `/-/resize/<WxH>/` перед именем файла:
  `…/<hash>/-/resize/400x400/file.jpg` (каталог/рекомы 400, карточка 1200, корзина 200).
  URL в `menu.json` (`photos[0]` или `editions[0].img`), ресайз делает фронт.
- Fallback — локальные копии `photos/dishes/<категория>__<блюдо>.jpg` (~89 МБ, в git НЕ коммитятся):
  `python3 parser.py photos` (нужен только на машине сборки/деплоя).
  Бэкенд раздаёт их как `/static/aidabaran/photos/dishes/…` — путь попадает в `photo_fallback`.
- Поведение ресайзера: вписывание с сохранением пропорций (итог может быть на 10–20% крупнее
  запрошенного), апскейла нет, кропа нет (кадрирование CSS `object-fit: cover`),
  несуществующий файл → честная 404 (поэтому `onerror`-fallback обязателен).

## Известные ограничения данных

- КБЖУ: 89/125 позиций с КБЖУ; 7 null; 28 напитков с текстом-описанием вместо КБЖУ (текст
  переносится в описание) и 1 десерт с текстом КБЖУ без слова «Калорийность» (warning при
  загрузке, KBJU пустой). Блок «Состав» показывается при непустых КБЖУ или описании, у позиций
  без обоих — не показывается (FR-07).
- Апсейл-опции только у 16 позиций.
- Ключи `upsell_map.json` — исходные апсейл-тексты с ценой (как в `menu.json`,
  `upsell_options[].name`); плагин сопоставляет ключ карты с `upsell_options[].name` после
  нормализации обеих сторон (отрезание хвостовой цены + trim), несопоставленные опции
  игнорируются (механика — `docs/30-contracts/recommender.md` §4).
- Карта ресторана — «рекламный материал»: перед пилотом сверить актуальность при визите.
- Дисклеймер карты: сервисный сбор 10% при компании от 6 человек — в v0 не моделируется
  («1 заказ — 1 рот»).
