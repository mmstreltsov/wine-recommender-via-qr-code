# ADR-0002: Core + плагин ресторана (изоляция специфики)

Дата: 2026-11-07 · Статус: принято

## Контекст
Требование масштабируемости «как Лего: подключил — заработало» (О5): ядро без специфики
ресторана, специфика (данные, рекомы, тема) — подключаемая. Решений-плагинов в Go несколько.

## Решение
- Специфичное = **Go-пакет в `backend/plugins/<restaurant>/`**, подключаемый build-time
  через registry в `main.go` (`RESTAURANT=aidabaran`).
- Единственный контракт: интерфейс `recommender.Recommender` (ForDish/ForCart) + типы данных ядра.
- Данные ресторана — файлы в `data/<restaurant>/` (меню, матрица пар, тексты, токены CSS).
- Фронт-специфика = CSS-тема + конфиг (имя/логотип из `GET /api/v1/config`).

## Отвергнутые альтернативы
- `plugin`-пакеты Go в рантайме: Linux-only, хрупкие ABI, лишние для 4–5 ресторанов.
- Отдельные сервисы на ресторан: операционная сложность не нужна прототипу.
- Конфиг-файл вместо кода-плагина: алгоритм рекомов с текстами и приоритетами в YAML не выразить
  без DSL — хуже для тестирования.

## Последствия
- Grep-проверка изоляции: в `backend/internal` и общих компонентах фронта нет слов «aidabaran»,
  грузинских категорий и т.п. (входит в DoD вех).
- Добавление ресторана = пакет плагина + data-каталог + тема CSS + 1 строка в registry.
