# ADR-0004: Рекомендации без ML — экспертная матрица + эвристики

Дата: 2026-11-07 · Статус: принято

## Контекст
Ограничение О4: без ML и рантайм-LLM. Данных о заказах нет (коллаборативная фильтрация невозможна).
Нужны: лента «топ-1 из каждой категории» (FR-10) и топ-1 корзины (FR-19) с текстами (FR-11/12).

## Решение — каскад источников для ForDish (по каждой категории-кандидату):
1. **Expert**: пара из матрицы `matrix.json` (руками, аналитик; текст готов).
2. **Upsell**: апсейл-опции самого ресторана (`upsell_options` в menu.json) → как дополнение позиции.
3. **Heuristic**: правило сочетания категорий плагина (напр. «суп → хачапури/чебуреки»),
   кандидат = топ позиции категории (порядок в menu.json = порядок сайта ресторана),
   текст — шаблон texts.go.

Для ForCart: правила покрытия «недостающего курса» (нет напитка → напиток; нет десерта → десерт;
иначе — дополнение к последней добавленной позиции), исключая уже лежащее в корзине; без кандидата →
рекомендация не показывается (FR-29).

Тексты обоснований — **статический контент**: черновики готовятся оффлайн (аналитик, допускается
LLM-ассист на этапе написания файла), в рантайме ничего не генерируется.

## Отвергнуто
- Рантайм-LLM/RAG («цифровой сомелье» банка) — нарушение О4 для v0, плюс зависимость от внешнего API.
- Контент-фильтрация по эмбеддингам/КБЖУ — псевдо-ML без валидации качества, риск бессмыслицы.
- Случайный подбор — убивает ценность обоснования (FR-11).

## Последствия
- Файл матрицы версионируется в git; CLI-валидатор (M1) проверяет: ссылки на item_id существуют,
  покрытие ≥ 1 пары для ≥ 80% блюд, тексты непустые.
- Качество = качество матрицы; веха M1 — ручная работа аналитика, не код.
