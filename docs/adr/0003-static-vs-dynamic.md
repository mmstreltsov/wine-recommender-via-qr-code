# ADR-0003: Статика в файлах, динамика в Postgres

Дата: 2026-11-07 · Статус: принято

## Контекст
Меню ресторана в прототипе статично (обновление = редкий перезапуск). Динамика — сессии, корзины,
события воронки. Спор: класть ли меню в БД.

## Решение
- **Меню/матрица/тексты** — файлы `data/<restaurant>/`, загружаются в память при старте сервера.
  `item_id` валидируется сервисным слоем по памяти (без FK на меню).
- **Сессии/корзины/события** — PostgreSQL (схема в `20-architecture.md` §4).

## Обоснование
- Меньше движущихся частей: нет сидов/синхронизации меню.
- Обновление меню = `python3 parser.py menu` + перезапуск (для пилота достаточно).
- События — единственная «растущая» таблица; она в БД с индексами, выгрузка CLI в CSV (AN-04).

## Последствия
- Перезапуск сервера сбрасывает кэш меню — приемлемо (дисклеймер в README данных).
- Целостность `cart_items.item_id`: позиции, удалённые из меню при обновлении, отсекаются
  сервисом при чтении корзины (строки в БД могут остаться — не проблема).
