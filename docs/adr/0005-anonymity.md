# ADR-0005: Анонимность гостя

Дата: 2026-11-07 · Статус: принято

## Контекст
Требование заказчика: не собирать персональные данные (О1) — иначе юридическая обвязка.
При этом нужна воронка по сессиям и столикам (A/B).

## Решение
- Аналитическая сессия `sessions.id` и credential в HttpOnly cookie `session` — независимые
  UUIDv4 из crypto RNG (ошибка RNG без fallback). Имя/UUID-форма/атрибуты cookie прежние
  (см. API; Max-Age из `COOKIE_MAX_AGE_H`, default 12ч). JS cookie не видит; привязки делает сервер.
- В БД только SHA256(lowercase canonical UUID credential), 32 байта, и абсолютный
  `expires_at = created_at + COOKIE_MAX_AGE_H` часов. Reuse не продлевает expiry, env не меняет
  существующий срок. Auth lookup только по hash AND `expires_at > now()`, никогда по id;
  ошибка БД — fail-closed. Credential/hash не выдаются в JSON/CSV и не логируются.
- `table_id` — только из URL QR (`?table=N`), валидируется (1–999), сохраняется в сессии.
- События и корзина ссылаются на session_id; никаких полей о человеке, никаких форм ввода.
- `localStorage` для гостевых данных не используется.

## Отвергнуто
- Fingerprinting (canvas/UA) — это сбор идентификаторов, против духа О1.
- Session в localStorage + Bearer: хуже для «открыл ссылку заново» и проще утечка.

## Последствия
- Cutover: заранее предупредить активных гостей о сбросе браузерного доступа к старым корзинам;
  остановить все старые бинарники до миграции 0003 и запуска новых. Не смешивать версии
  и не откатываться к старому ID-auth; небезопасный legacy fallback запрещён.
- Миграция 0003 additive: nullable unique `credential_hash bytea`, nullable `expires_at timestamptz`;
  CHECK: оба NULL (legacy) либо оба non-NULL и hash длиной 32 байта. Не backfill из id,
  не удалять sessions/carts/events и связи: исследовательские данные сохраняются.
- Legacy cookie намеренно недействителен: новая анонимная сессия/table из текущего запроса,
  пустая новая корзина и новый cookie с обычным rate-limit. Исторический CSV UUID доступа не даёт.
- Очистка cookie = новая сессия: приемлемо, воронка не ломается.
- Malformed/unknown/expired cookie либо записи в БД уже нет → сервер создаёт новую
  сессию и ставит новый cookie; корзина гостя обнуляется, события старой сессии остаются
  в аналитике. Серверный expiry обязателен в M5 и не удаляет исторические данные.
- Retention-удаление сессий старше 90 дней — Cron/CLI на этапе VPS (не v0-блокер);
  это отдельная будущая политика хранения, не срок действия credential и не часть cutover.
