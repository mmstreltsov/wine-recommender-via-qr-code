# 40. Frontend: экраны, состояния, путь гостя

Mobile-first (QR → телефон). Роуты: `/` (меню), `/dish/:id`, `/cart`, `/pay-stub`.
Все данные — через API (`30.2`), никакой ресторанной специфики в коде: только CSS-переменные
темы + `GET /config`. Тест-раннер: vitest + @testing-library/react.

Изменения рекомендаций от 10.11.2026 ниже являются согласованной post-M5 целью, не уже
принятой реализацией. Новые AC pending: [`recommendation-improvements.md`](reports/recommendation-improvements.md).

## Тема (UI-01…03)
- `theme/aidabaran.css` — значения из `data/aidabaran/assets/tokens.css`: `--c-accent:#fdc300`,
  чёрный/белый/серый, `--font-display:'Unbounded'`, `--font-text:'Montserrat'`, радиус 10px.
- Шрифты Unbounded и Montserrat (кириллица) — self-host woff2 в `data/aidabaran/assets/fonts/`
  (маршрут `/static/aidabaran/assets/fonts/`), `font-display: swap`; Google Fonts не
  используется (внешняя точка отказа).
- Компоненты используют только переменные. Кнопка: жёлтая, чёрный текст, без рамки/тени,
  `transition: .2s ease-in-out`. Чип: белый фон + рамка 1px чёрная; активный/hover → жёлтый.

## Фото (FR-26)
`PhotoWithFallback`: берёт `photo_url`, вставляет `-/resize/{W}x{W}/` перед именем файла
(каталог 400, карточка 1200, корзина 200), `onerror` → `photo_fallback`, если и его нет —
плашка-заглушка с иконкой. Всегда `loading="lazy"`, `object-fit: cover`. Подробности поведения
CDN — `data/aidabaran/README.md`.

## Экраны и состояния

### 1. Меню `/` (FR-01…04, FR-25…27)
- Шапка: логотип+название (из config), бейдж корзины (счётчик, жёлтый) → `/cart`.
- Чипы категорий, горизонтальный скролл: «Все» + категории из ответа `GET /menu` (полное
  меню — 14, FR-02), активный жёлтый. Пустых категорий не бывает: сервер не отдаёт категории
  без доступных позиций (FR-36/37).
- Сетка карточек: ≤560px — 1 колонка; 561–960px — 2; >960px — 3 (источник —
  `data/aidabaran/assets/tokens.css`). Карточка: фото, название, цена (Unbounded),
  визуально кликабельна (hover/active, tap ≥ 44px).
- Состояния: skeleton при загрузке; ErrorRetry при ошибке (FR-35); пустых данных не бывает
  (меню статичное), но guard обязателен.

### 2. Карточка блюда `/dish/:id` (FR-05…15, FR-28…30)
Сверху вниз:
1. Назад (в контекст входа, правила ниже; без контекста — в меню). Большое фото (resize 1200).
2. Название, цена + кнопка «Добавить в корзину» (source контекста входа;
   `menu_add_click`/`rec_add_click` пишет только сервер на POST).
3. Блок «Состав»: `kbju` + `description`; показывается, если непусто `kbju` ИЛИ `description`;
   пусты оба — блока нет (FR-07).
4. Апсейл-опции позиции (если есть): список «Название +420₽» — отображение только (добавление
   опций в v0 не реализуем — вне скоупа; блок помечен как информация).
5. Разделитель + подзаголовок **«Хорошо сочетается с»** (FR-13, текст из config).
6. Лента RecCard (вертикально, 1 колонка, серверный порядок без пересортировки): крупное фото
   над текстом, название, цена, `reason_text`, кнопка «Добавить». Фото/текст являются ссылкой
   на `/dish/:id` рекомендованной позиции (FR-15); «Добавить» — отдельная соседняя кнопка,
   не вложенная в ссылку, без перехода. «Добавить» → POST
   `source=rec_feed`, мини-подтверждение (бейдж корзины +1, кнопка меняется на «✓ Добавлено»
   на 1.5s). Скрытые состояния: лента пуста → блока нет (FR-29).
- Impression-трекинг: IntersectionObserver ≥50%; `rec_impression` дедуплицируется в рамках
  одного открытия карточки (dish_id + монотонный счётчик открытий), повторное открытие карточки
  генерирует новые rec_impression для показанных рекомов (`rec_feed_visible`).
- Состояния: skeleton, 404 → ErrorRetry с кнопкой «В меню», ошибка сети → ErrorRetry.

#### RecCard и контекст перехода (FR-05/09/14/15/30, AN-02, NFR-01)

- Единый вид для ленты и рекомендации корзины: фото сверху с соотношением 4:3, на мобильном
  на всю доступную ширину карточки; на desktop ширина карточки/фото ограничена контейнером,
  не растягивается на весь широкий viewport. Ниже текст/цена/обоснование/добавление.
  PhotoWithFallback и lazy-load сохраняются; горизонтального переполнения нет.
- Ссылка фото/текста и соседняя кнопка доступны с клавиатуры, имеют понятные названия и
  видимый фокус, интерактивные targets ≥44×44px. Добавление не активирует ссылку и наоборот.
  Detail сохраняет состав, цену, добавление и собственную ленту рекомендаций.
- Внутренний router history state хранит только проверяемый контекст: источник входа
  `menu|rec_feed|rec_cart`, внутренний экран возврата, состояние фокуса/скролла. Возврат
  разрешён лишь к существующим роутам приложения (меню, исходный detail или корзина),
  с валидным ID; произвольные URL, внешние/protocol-relative адреса и скриптовые схемы
  запрещены. State недоверенный: malformed/отсутствующий → безопасное меню и source `menu`.
  Не использовать HTTP Referer, строковый `returnTo` из query или секреты/данные сессии.
- Вход из меню задаёт `menu`, из ленты detail `rec_feed`, из рекомендации корзины `rec_cart`.
  Экранный «Назад» и browser Back возвращают к исходному экрану, восстанавливают прокрутку
  и фокус на открывшую ссылку; если она исчезла после мутации, фокус на доступный заголовок
  секции/экрана. Не выполнять history-back вслепую при отсутствии валидного контекста.
- Source принадлежит конкретной записи истории и сохраняется при Back/Forward/refresh.
  Прямой URL/новая вкладка без state работают с меню-fallback. Для A → rec B → rec C
  источник C = `rec_feed` от непосредственной ленты B, даже если B открыт из корзины.
  Добавление самой позиции из detail использует source её входа; добавление из её
  собственной ленты всегда `rec_feed`. Обновление данных/корзины не сбрасывает источник.
- `dish_card_open` передаёт source входа; add-события остаются серверными. Сохранить
  IntersectionObserver ≥50% и дедупликацию по открытию detail: наблюдаемые области карточки
  и ленты должны реально достигать порога на 375px (включая длинные тексты), без отправки
  показов до видимости и без дублей на простом rerender. Для длинной ленты наблюдается
  достижимая область её начала, а не вся многокарточная секция.

### 3. Корзина `/cart` (FR-17…21, FR-23, FR-31, FR-32, UI-04)
- Шапка с бейджем. Список CartLine: фото-превью (resize 200), название, цена×qty, степпер −/+,
  крестик удаления (правый верхний угол, FR-18).
- Недоступная линия `available=false` (UI-04, FR-37): приглушённое отображение + бейдж
  «Нет в наличии»; крестик и степпер работают (удаление и изменение qty не запрещены). Кнопка
  «Оплатить» при наличии таких линий не ведёт на заглушку: понятное сообщение («Часть позиций
  больше нет в наличии — уберите их из заказа»).
- Итог: «Итого: N ₽» (Σ price×qty, FR-23).
- Блок «Хорошо сочетается с» → одна RecCard с кнопкой «Добавить» (`source=rec_cart`).
  Фото/текст открывают detail с контекстом `rec_cart`, без изменения корзины; вид RecCard
  и возврат описаны выше. Пересчёт — с каждым ответом API (FR-20, реком в ответе корзины).
  null → блок скрыт, в том числе у завершённого заказа/после исчерпания допустимых связей;
  фронт не добавляет свою fallback-рекомендацию.
- Кнопка «Оплатить» (жёлтая, sticky снизу) → `pay_click` → navigate `/pay-stub` (кроме случая
  блокировки UI-04: линии `available=false` — сообщение без перехода, без `pay_click`).
- Пустая корзина: иллюстрация-плашка «Корзина пуста» + кнопка «Перейти в меню»;
  без оплаты/рекомов (FR-31).
- Состояния: skeleton, ErrorRetry.

### 4. Заглушка `/pay-stub` (FR-24)
Текст дословно: **«Ваш выбор сформирован. Позовите официанта.»** + `stub_view`
событие + кнопка «Вернуться в меню». Больше ничего.

### 5. Ошибка (FR-35, общий компонент ErrorRetry)
«Что-то пошло не так, попробуйте ещё раз» + кнопка «Повторить» (повторяет последний запрос).
Никаких кодов/стеков. Офлайн (fetch reject) — тот же экран.

## Сессия и события (FR-33/34, AN)
- table_id: фронт при старте, если в URL документа есть валидный `?table=N`, добавляет `?table=N`
  к первому API-запросу в рамках загрузки страницы (например, `GET /api/v1/menu?table=12`).
  Сервер учитывает `table` только при создании сессии; в живой сессии повторные сканы table не меняют.
- Сериализация старта: фронт обязан завершить первый API-запрос (`GET /menu`, с `?table=N`
  при наличии) до отправки любых других /api-запросов — исключает гонку создания сессий
  и потерю table_id.
- Клиентские события — тонкий трекер: очередь + `navigator.sendBeacon` при unload,
  обычный POST иначе; дедупликация `rec_impression` — в рамках одного открытия карточки блюда
  (dish_id + монотонный счётчик открытий), повторное открытие генерирует новые события.
  При `429` событие молча дропается без ретраев.

## Путь гостя (цель — без тупиков)
Меню → карточка → (лента/кнопка) → корзина → оплата-заглушка → меню.
Фото/текст рекомендации в ленте или корзине → detail с собственной лентой → возврат в
исходный контекст. Это существующий роут, не новый уровень/экран или модалка.
Обычная линия корзины по-прежнему не становится ссылкой: изменение относится к RecCard.

## Чего на фронте НЕТ
Форм ввода, авторизации, тостов с техошибками, десктоп-специфики (только адаптив),
библиотек состояний (useState/context достаточно), UI-китов.
