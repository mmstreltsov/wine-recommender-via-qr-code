# AGENTS.md — правила работы в этом репозитории

Проект: **«Свое Шеф»** — QR-сервис для гостей ресторана: гость сканирует QR за столом, открывает
онлайн-меню, видит рекомендации «что добавить к заказу» с обоснованием, собирает корзину,
оплата — заглушка. Цель прототипа — собрать данные воронки для исследования проблемы.

**Прочитай перед работой:**
1. `docs/00-context.md` — что за продукт, боль, метрики, ограничения (без ПДн!).
2. `docs/10-requirements.md` — реестр требований с acceptance-критериями. Единственный источник правды о скоупе.
3. `docs/30-contracts/` — контракты (API, данные, реком-движок, события). Менять их можно только через PR в docs + согласование.
4. `docs/40-frontend.md` — экраны и состояния.
5. `docs/50-plan.md` — вехи и DoD.
6. `docs/60-agents.md` — команда агентов: роли, права на запись, loop апрувов.

## Структура репозитория

```
docs/                 # спецификации (источник правды)
data/aidabaran/       # данные пилотного ресторана: menu.json (кухня), barmenu.json (бар, v0 не используется),
                      # assets/tokens.css (дизайн-токены), parser.py (обновление данных/фото)
backend/              # Go: API + события + реком-движок (интерфейс)
backend/plugins/aidabaran/  # специфика ресторана: загрузка данных, матрица пар, тексты
frontend/             # Vite + React + TS, мобильный-first, тема = CSS-токены
```

## Стек

| Слой | Технологии |
|---|---|
| Backend | Go 1.22+, stdlib `net/http` (без фреймворков), `pgx/v5`, миграции `goose` (SQL-файлы), Docker Compose |
| БД | PostgreSQL 16 (динамика: сессии, корзины, события). Меню — статика из `data/` в памяти процесса |
| Frontend | Vite + React 18 + TypeScript (Node 20+), CSS-переменные (без UI-китов), компоненты в `frontend/src/components` |
| Инфра | docker-compose: postgres + backend (backend раздаёт собранный фронт статикой) |

## Команды

```bash
# инфраструктура (postgres)
docker compose up -d db

# backend
cd backend && go build ./... && go test ./... && golangci-lint run
cd backend && make migrate-up                # goose up
cd backend && go run ./cmd/validate-matrix   # валидатор матрицы/данных (M1)
cd backend && go run ./cmd/server            # API на :8080
cd backend && go run ./cmd/server export-events > events.csv   # выгрузка событий для исследования

# frontend (Node 20+)
cd frontend && npm ci && npm run dev         # :5173, проксирует /api на :8080
cd frontend && npm run lint && npm run test && npm run build

# всё вместе (дев)
docker compose up
```

## Правила

- **Без ПДн**: никаких имён, телефонов, логинов, профилей. Анонимная сессия = UUID в HttpOnly cookie.
  Вводимые гостем данные нигде не сохраняются. Аналитика — только события UX (см. `docs/30-contracts/events.md`).
- **Безопасность — высший приоритет**: параметризованные SQL-запросы (никакой конкатенации),
  валидация всех входных данных, секреты только через env (`.env` в git не попадает),
  ошибки наружу без внутренних деталей (стеков, путей, схемы БД).
- **Traceability**: каждый тест и каждая meaningful правка связана с ID требования (`FR-XX`, `AN-XX`, `UI-XX`, `NFR-XX`).
  Тесты называются `TestFR07_...`. В конце вехи заполняется колонка трассировки в `docs/10-requirements.md`.
- **Контракты — источник правды**: код реализует `docs/30-contracts/`, а не наоборот. Расхождение = баг.
- Специфика ресторана живёт ТОЛЬКО в `backend/plugins/aidabaran/` и теме фронтенда (`frontend/src/theme`).
  `backend/internal` и общие компоненты фронтенда не содержат упоминаний АйДаБарана, грузинской кухни и т.п.
- UI-тексты — на русском. Идентификаторы кода — английские. Комментарии в коде не добавлять без необходимости.
- Не добавлять зависимости без необходимости; перед добавлением — обоснование в описании задачи.
- DoD любой задачи: тесты + lint зелёные, трассировка обновлена, ручной сценарий по acceptance-критериям пройден.
